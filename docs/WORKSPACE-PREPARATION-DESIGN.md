# 工作区准备与笔记本进入

状态：首期调整已实施。保留现有启动屏障和导航事务；暂不抽取独立的通用准备模块。

## 目标与边界

启动继续分为两个阶段：阶段 1 保留版本首次执行一次的初始化门槛；阶段 2 每次启动准备当前工作区。普通笔记本切换和新建后进入继续使用自己的局部导航事务，不重新打开启动全屏 loading。

当前阶段优先消除已经确认的重复请求与无效等待，并复用成熟的 `selectNotebook` 事务处理新建后的进入。卡片、文件夹和会话列表仍由各自 loader 加载。后台导入、模板设置和云同步继续使用各自的进度与错误状态。

只有当首期实现后仍出现多处重复的准备规则，才考虑抽取共享模块。启动专属屏障、列表数据和导航事务仍各自保留在原有状态归属中。

## 已实施

- `getStartupListTask` 在没有选中笔记本或列表列隐藏时不注册列表等待；会话视图只在列表实际可见时等待。
- `waitForStartupTask(null)` 立即结算为 ready；其余阶段 2 任务仍等待当前可见列表、初始文档和工作区表面。
- 笔记本切换不再从导航事务直接调用 `loadNotes`。选择变化后由 `MemoListDataLoader` 或文件夹／会话 loader 负责唯一的数据请求；文件夹模式不额外加载卡片列表。
- `selectNotebook` 接受显式的 `workColumnTarget` 策略。普通切换默认保留工作区目标，新建进入传 `clear`，在同一事务中保存旧文档、切换上下文、清空目标并提交。
- 新建注册结果暂存于 hook 中。进入失败后使用相同输入重试会复用已注册的笔记本，避免重复创建。
- 云端恢复可先注册而不切换原生上下文，再由同一个 `selectNotebook` 事务完成保存旧文档、激活和清空目标。命令默认仍激活，保持既有调用兼容。
- 新建进入回滚时，前一个原生笔记本为空也会恢复为 null。

## 入口规则

| 入口 | 进入行为 | 后台工作 |
| --- | --- | --- |
| 启动 | 原生 ready、笔记本上下文、工作区恢复；等待当前可见首屏数据 | 版本首次初始化只由既有门槛控制 |
| A→B | `selectNotebook(B)` 默认保留工作区目标；数据 loader 独立加载 B | 导入和同步不重新打开启动 loading |
| 普通新建 | 注册后调用 `selectNotebook(created, { workColumnTarget: 'clear' })` | 普通导入／模板设置维持原有状态和重试 |
| 首次创建 | onboarding 继续调用普通 `selectNotebook`，保留引导完成及导入启动顺序 | 导入完成不作为关闭引导的前置条件 |
| 云端恢复 | 注册时不激活，再通过 `selectNotebook` 进入并清空旧目标 | 云同步独立运行，不启动普通导入或引导填充 |

## 暂不做的扩展

- 不把启动屏障改造成可供所有导航复用的任务框架，也不新增通用任务注册、取消和轮次系统。
- 笔记本切换提交后，列表由现有 loader 展示其局部 loading 与错误；切换事务不等待列表完整首屏。若后续产品要求切换期间也等待完整首屏，再基于具体体验需求设计局部屏障。
- 本轮不改造 onboarding 的事务和后台任务生命周期；它已复用 `selectNotebook`，其创建结果与引导持久化重试保持原样。

## 关注点

- 空列表是合法 ready；列表读取错误仍由列表自身呈现和重试。
- 连续切换依赖现有导航 requestId 和原生笔记本转换锁。过期导航不得覆盖当前前端提交。
- 如果新增首屏必需数据，应先确认它当前可见，再加入启动等待；隐藏列表、隐藏标签页、后续分页和后台内容生产不应阻塞阶段 2。
- 如果普通新建进入失败，保留注册结果只用于同一组输入的重试；不同输入开始新建时丢弃旧缓存。
