# 系统打开本地文档

Windows 冷启动参数、第二实例参数和 macOS `RunEvent::Opened` 最终交给
`app/flowix-desktop/src/app/open_targets.rs`。系统文件关联支持 `.md` 和
`.markdown`；深链接继续交给前端的笔记链接解析器。

## 请求交接

- 原生层将请求放入进程内的 `PendingOpenTargets`，事件只用于通知有新请求。
- 前端在底层 Tauri 监听器注册成功后读取待处理请求，也会在收到通知时重新读取。
- 请求带有 ID，前端接收后调用确认命令。读取快照不会删除请求，确认只删除指定 ID。
- 同一类消费者的交接串行执行，避免组件卸载重挂时重复执行尚未完成的打开操作。
- 笔记本内文件的导航等待前端工作区初始化完成；笔记本外文件交给对话框，按批次排队。
- 确认代表请求已交给前端导航或对话框，并不代表文件读取成功。读取失败由文档视图处理。
- 请求和授权只在本次应用进程内保留，不提供跨进程恢复。

## 授权与错误

原生文件路径先解析为文件系统规范化路径，并授予 `main` 窗口单文件访问权限。
授权失败时记录来源及错误，并提交失败提示，不继续提交该文件的打开请求。
笔记本归属判断复用后端路径范围判定；深链接不会为任意外部路径新增授权。

读取阶段分别提示应用访问授权不足和操作系统读取权限不足。系统权限错误使用
`DOCUMENT_READ_PERMISSION_DENIED` 标识，避免依赖 Windows/macOS 的错误文本。
文档加载失败日志保留原始错误及运行时文档标识。

## 针对性验证

- `pending-requests.test.ts`：无通知的冷启动请求、处理中收到新请求、卸载重挂和交接失败。
- `open_targets.rs`：确认前保留请求、消费者隔离、序列化协议、单文件授权范围和授权失败。
- `external_document.rs`：操作系统读取权限错误的稳定标识。

真实 Windows 文件关联和 macOS Finder 激活仍需使用对应平台安装包验收。
