# 文档模块整理

## 约束

- 笔记继续按路径寻址，运行中的编辑会话使用 displayId。
- 集合使用 collectionId；所选 viewId 属于展示实例。
- 保留保存队列、CAS、操作回执、恢复草稿和各领域状态。
- 每迁移一种行为即删除对应旧协调逻辑，不建立万能资源服务。

## 职责

| 位置 | 负责 | 不应承担 |
| --- | --- | --- |
| 后端领域操作 | 持久化、索引、持久引用、失败恢复 | 依赖前端事件补齐持久一致性 |
| 文档会话 | 编辑缓冲、保存基线、冲突、草稿 | 文件树查询 |
| 集合领域 | 配置、dataset、views、结构校验 | Markdown 缓冲 |
| 工作区 | 展示、导航、恢复位置 | 文件持久化 |
| 查询消费者 | 按影响范围刷新结果 | 自行协调跨领域路径迁移 |
| 传输适配 | 解释旧消息、提供类型化契约 | 从 fs modify 推断正文已经变化 |

## 已开始的迁移

`platform/tauri/notebook-change-events.ts` 是旧 `flowix:path-note-changed`
通道的类型化边界，不增加第二条广播通道。

- `path-moved`：带确认的旧／新相对路径和 directory。
- `resource-deleted`：带删除路径。
- `query-invalidated`：指定路径或整个笔记本需要重新查询，不代表内容提交。

全部现有前端路径通道消费者改用此入口。内容提交仍由 memo-event 和
文档监听现有机制处理，集合配置仍保留 collection-changed。
笔记移动和标题重命名现在也发送完整移动信息。

## 第二阶段实现

- 后端 `commands/path_change.rs` 定义确认移动事实；文件／目录命令响应中的
  `notebookChange` 与广播携带相同 `changeId`。集合用 notebookId 和已存在
  的 operationId 构造相同标识，不引入第二条广播通道。
- 前端 IPC 适配器将命令结果交给 `subscribeNotebookChanges` 的同一消费者。
  每个消费者维护有界的去重集合，避免一个消费者抑制其他消费者。
- 对外的 files.rename/move/renameFolder/moveFolder 仍返回路径字符串。
  兼容前端 HMR 已更新而旧后端尚未重启时的旧字符串响应。
- 文档层拒绝过期迁移时，工作区停止对应导航迁移；重复确认同一目标地址
  不重复更新文档历史。
- 路径移动遍历全部运行身份，而非只看激活文档；批量期间暂停身份回收。
  工作区更新打开位置、目录上下文、媒体、集合、恢复目标和文档历史，保留
  展示身份、视图选择、焦点及其他宿主状态。
- 恢复草稿按持久地址迁移，覆盖无运行身份的关闭草稿；与路径通知队列串行，
  避免下一次移动在上一次草稿迁移结束前开始处理。
- 主窗口移动与删除共用顺序队列。笔记专用移动／重命名也接入 watcher
  move guard 和 lease rebase，失败退出释放 guard。
- 置顶读取 notes 中的 favorited 投影，新增直接消费笔记本变更的刷新入口，
  旧请求结果由 requestSequence 隔离，不先清空已有组。
- 移除笔记专用操作的重复链接任务提交；其余相邻相同任务在队列合并。

### 持久一致性边界

目录移动沿用 core `rename_indexed_path`：notes、派生索引、内容版本地址与
媒体地址在 notebook DB 事务中迁移，失败执行文件和索引回滚。
置顶是 notes 的属性，不是前端缓存或独立的置顶列表表。
笔记专用移动沿用 NoteService：磁盘为事实，索引失败写 pending-refresh
标记并保留原有修复机制。集合引用更新保持 CAS，发生并发编辑时不覆盖。
这些机制不等于跨文件系统与多个配置文件的全局事务。

### 当前限制

changeId 解决同一确认事实的重复投递，不是版本号；本地队列保留接收次序，
不会为任意乱序、缺失的外部事件推测资源身份。原始 watcher 的无标识通知
仍需按路径安全应用；外部变化全面核对与恢复属于第四阶段。
非笔记本访问目录继续保留原有命令调用方的路径处理。


## 后续交付顺序

### 第三阶段进度

- `prune_missing_memo` 清理失效路径索引和表格引用后，即使没有旧 memo
  compatibility row，也会发出带 changeId 的路径删除事实。有 memo row 时仍走
  MemoEvent，避免同一删除广播两类删除事件。
- 删除事实由各查询消费者按范围处理：笔记列表合并 24ms 后重查，置顶区跳过普通
  新建事件并消费用户删除及云同步 MemoEvent；主窗口另行刷新标签与待办派生元数据。路径删除路由
  清理浏览器标签，以及工作区当前、pending、previous、选中笔记和持久恢复目标中
  命中的文件路径。若 previous 是唯一命中项，只移除回滚地址，保留当前有效视图。
- 缺失笔记提示和列表删除入口不再重复本地刷新／关闭；由 MemoEvent 或路径删除
  事件统一更新所有窗口。删除前的保存检查和成功提示仍由调用处负责。
- 普通创建、模板创建和导入都返回并广播同一个 `NotebookPathCreated` 回执。
  前端命令回执和广播进入同一订阅边界，以 changeId 去重；旧桌面进程缺少回执时，
  前端用已确认的创建结果刷新当前窗口。
- 普通新建与模板创建结果就地 upsert。模板创建和批量导入不再额外发起重复列表
  查询。创建回执携带发起窗口标识；发起窗口由命令结果 upsert，其他窗口重查，
  批量导入在本地逐项 upsert。
- 笔记属性继续使用文档保存队列；保存回执由文档会话消费，路径失效通知刷新列表。
  颜色、置顶和自定义筛选的调用处保留即时行内 patch，不再额外触发整表查询。
- 集合引用的内容刷新由 `collection-changed` 或外部路径变化负责；本地集合回执只
  更新路径跟踪，不再触发同一个引用重复读取。目录集合移动会在集合变更通知中携带
  移动范围，驱动嵌套集合引用和目录清单刷新；文件树按目录范围迁移缓存，并抑制随后
  到达的重复文件系统通知。

已定位的入口：前端笔记操作在 `memo-document-operations.ts`，普通文件
在 `local-document-operations.ts`，集合在 `collection/mutations.ts`；
桌面命令分别进入 `commands/memo`、`commands/file.rs` 和
`commands/collection.rs`。入口核对如下：

| 写入来源 | 持久化和索引 | 前端通知／会话 | 失败边界 |
| --- | --- | --- | --- |
| 界面笔记创建、保存、删除 | 路径型 `NoteService` 更新 Markdown 和 notebook 的 SQLite `notes` 投影；路径命令不要求兼容 Memo 行 | 创建回执和 `flowix:path-note-changed` 由同一适配边界消费；路径编辑会话使用保存队列及提交回执。仍走旧 Memo 模型的操作继续发 `memo-event` | 磁盘是笔记正文事实；路径索引可重建，Memo 兼容清理不应阻止已确认的路径删除通知 |
| Agent 的 Flowix CLI/MCP | `flowix-cli/src/path_store.rs` 通过 core `NoteService` 创建、CAS 保存、删除；不经过前端服务，直接更新路径索引 | 桌面文件监听刷新查询；外部创建发 `resource-created/source=external_tool`，可按既有偏好自动打开；活跃文档由外部文档监听器通知 | CLI 与桌面端不共享命令回执；关闭应用期间的变更由下次索引 reconcile 收敛 |
| Agent shell、外部编辑器和其他进程 | 直接写 notebook 文件时，桌面文件监听器按路径刷新可重建索引，并记录本地云同步变化 | 文件监听发移动、删除或查询失效；当前打开的路径另由 `ExternalDocumentWatchState` 的原生监听和 750ms 修订轮询通知，未保存缓冲走外部变更合并 | 外部内容事件发送失败会保留修订供轮询重试；主文件监听不可用或索引刷新失败时依赖 watcher 重绑／启动 reconcile |

Agent 的 Flowix CLI/MCP 与 Agent shell 是两种写入路径：前者经过 `NoteService`，后者
由文件系统监听发现。路径型笔记不创建兼容 Memo 行，因此外部写入不会伪造
`MemoEvent::Created/Updated`；`MemoChangeSource::ExternalTool` 保留给仍以 Memo 为事实的
调用方。外部创建使用路径事件表达来源，并由工作区按既有偏好决定是否打开。

失败边界仍需注意：进程级文件监听不是持久消息队列；应用关闭期间没有 UI 实时通知，
恢复依靠启动 reconcile。索引数据库持续不可写时，磁盘操作与查询投影可能暂时分离，
当前仍依赖后续 watcher 重试或 reconcile 修复。

### 第四阶段进度

- 将导航离开从 `flushDocumentPath` / `flushWorkspaceDocumentPath` 改名为
  `prepareDocumentLeave` / `prepareWorkspaceDocumentLeave`。它只保留会话并启动
  保存与恢复草稿，不再让调用名暗示磁盘写入已完成；文档切换仍不等待文件 I/O。
- 版本恢复、版本归档、路径笔记删除使用 `saveDocumentPath`，先捕获编辑器最终
  内容并等待标题和正文保存队列完成，再做覆盖或删除。路径删除不再额外拼接
  一个调用方级 save-queue 等待。
- `DocumentStore` 的生命周期注释同步说明了导航准备与破坏性写入的不同保证。

第四阶段本轮又复核了外部变化与路径迁移交错时的恢复草稿地址，以及退出超时后重试
与动态编辑捕获器的收尾行为。也静态复核了打开与导航补偿入口：会清理文档会话的操作
由 `clearDocument` 统一准备一次，保留会话的目标走显式准备；没有发现同一导航事务重复
协调的调用链。第四阶段没有运行自动测试或完整运行时验收。

本轮第四阶段继续处理了打开、恢复和外部变化的交界：

- 文档加载和恢复草稿读取都按当前路径核对。加载期间发生路径移动时，旧路径的
  读取结果不会落进新路径会话，而是针对移动后的路径重新读取；恢复读取的去重键
  也包含路径，避免复用旧地址的草稿请求。
- 打开时发现恢复草稿与磁盘相同，不再把它重新挂成未保存缓冲，并在没有待恢复标题
  时清除已完成保存遗留的草稿；草稿与基线相同但内容较新时，也会进入普通条件保存，
  不会只显示在内存里而不触发写回。
- 恢复存储读取超过 10 秒会显示可重试的读取错误，不再被当作“没有草稿”继续打开；
  这避免慢 IPC 时新编辑覆盖尚未读出的旧恢复草稿。
- 文档加载结束会把 `ready` 或 `unavailable` 结果写入文档转换状态。启动等待会等
  当前转换结束；被新导航替换时继续等待新目标，加载失败会让首屏进入 degraded，
  保留本地错误／重试入口。
- 活跃文档收到外部删除时取消尚未开始的保存计时，先保护未保存内容，再读取路径
  实际状态以展示缺失笔记入口。读失败会使会话缓存标记为未加载，重试会重新读盘。
  外部不可用错误也映射为缺失笔记状态。
- 退出准备设有 16 秒前端截止时间，为桌面端 20 秒多窗口握手预留应答时间。单窗口
  的 flush 会在首次保存后检查是否出现新文档会话／持久化适配器，并最多补做一轮；
  工作区持续变化或超时会拒绝本次关闭，让用户仍可重试。
- 关闭握手开始后暂时冻结窗口输入；两轮 flush 结束前再次检查新编辑捕获器、未保护的
  正文／标题草稿及待执行保存计时。超时后仍在运行的会话 flush 由单飞协调复用，避免
  用户重试时并发启动第二个 flush。
- 全局退出等待期间新挂载的文档窗口会加入当前参与集合并收到同一退出请求，避免
  退出快照之后打开的窗口没有保存确认机会。
- 异步保护草稿时按运行时 display identity 解析最新路径，避免目录重命名与外部变化或
  退出保存交错时，把恢复草稿写到已过期的旧路径。
- 工作区切换到会清理文档会话的媒体／集合目标时，不再在调用方和 `clearDocument`
  各准备一次同一文档。仍保留文档会话的网页和文件夹选择器走明确命名的
  `prepareActiveWorkColumnDocumentLeave`。
- 删除当前笔记本前改用 `saveWorkspaceDocumentPath` 等待标题与正文保存完成；一般
  工作区离开继续走后台准备。`flushWorkspaceDocument` 的兼容适配已在第五阶段移除。

本轮代码级修复与静态复核已完成；第四阶段仍待用户后续统一运行时验收。自动测试未运行。
