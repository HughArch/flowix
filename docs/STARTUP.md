# 启动阶段与任务接入

桌面端启动分为三个阶段。阶段 1 是当前应用版本的一次性初始化；阶段 2 在每次启动运行，负责让当前笔记本和工作台 shell 可用；阶段 3 在工作台首次绘制后放行内容恢复和非阻塞服务。阶段 3 不延长阶段 2，也不增加第二层全屏 loading。

| 阶段 | 目标 | 主要工作 | 就绪边界 |
| --- | --- | --- | --- |
| 1. 版本初始化 `initialization` | 升级当前版本所需的数据 | 数据库路径兼容、数据库准备、结构与持久化格式迁移、一次性修复、运行时准备 | 当前版本的持久化完成记录写入成功。正常启动跳过已完成的版本初始化 |
| 2. 工作区准备 `workspacePreparation` | 展示可交互的工作台 | 准备当前本地存储、读取笔记本注册元数据、选定当前笔记本、初始化前端笔记本上下文 | 原生依赖 ready，笔记本身份与上下文可用，前端 shell 已绘制 |
| 3. 绘制后工作 `stage 3` | 恢复内容并启动独立服务 | 恢复保存的工作区目标、可见视图加载内容、Agent 恢复、Cloud 初始化、CLI 探测、更新检查、笔记和媒体维护等 | 各任务按所属功能完成或报告自身失败；不改变阶段 2 的就绪结果 |

原生 `StartupStatus.stage` 只表示阶段 1 和阶段 2，`phase` 表示 `pending/running/ready/failed`，`step` 标记当前任务。前端 `useWorkspaceStartupStore` 跟踪原生状态及工作台前台状态。阶段 3 是工作台绘制后的准入点，不是第三个全屏启动屏障。

## 阶段 1：版本初始化

初始化进度包含数据库路径处理、数据库准备、迁移 job 和运行时准备。笔记本文件扫描和工作区内容恢复不属于阶段 1。阶段 1 仅在当前应用版本尚未完成初始化时运行。

迁移通过 `storage_initialization.rs` 的 `initialize_legacy_storage_with_progress` 接入，并使用稳定且唯一的任务 ID，例如 `feature_schema_v2`。迁移内容变化时使用新 ID，不复用已完成 ID。新增全局 job 时同步加入 `GlobalInitializationJob::ALL`，使任务计数和执行定义保持一致。

迁移必须能够安全重试，因为操作成功后、完成记录写入前仍可能中断。必需迁移失败会阻止阶段 2 并保留失败状态；可选迁移失败不写完成记录，但不因此在同一版本的每次启动重新打开阶段 1。不能移除版本完成判断，也不能为发现新增任务而每次启动重跑阶段 1。

## 阶段 2：工作区准备

原生必需准备由 `spawn_workbench_startup` 调用 `prepare_startup_storage` 和 `prepare_notebook_selection`，使用 `StartupStage::WorkspacePreparation`；任务成功前原生状态保持未就绪。当前笔记本选择从本地注册元数据解析，不探测所有外部目录或磁盘。

前端 `performMainWindowStartup` 按依赖顺序等待原生 ready、笔记本身份和笔记本上下文。随后释放 shell，等待 `MainLayout` 在 Suspense 边界内挂载，再给浏览器绘制机会，最后发送 `notifyStartupInteractive`。这个信号表示工作台或重试界面已挂载并有机会绘制，允许后台服务开始；它不表示恢复的文档或全部首屏数据已经加载。

笔记本注册元数据读取失败时显示失败和重试界面，不将错误伪装成空笔记本列表。并发挂载共用一次启动 Promise，避免重复初始化。前端必需元数据任务加入 `performMainWindowStartup` 并等待其结果；不要把文档读取、列表加载或面板水合重新加入阶段 2 的等待链。

## 阶段 3：工作台绘制后

前端通过 `admitStartupStage3` 在 `MainLayout` 挂载并经过绘制机会后放行非必需任务。`runStartupStage3Task` 按 WebView 内的任务名去重；它提供准入和去重，不是共享队列，也不提供统一重试策略。每个任务保留自己的失败处理和重试入口。

- 保存的工作区目标开始异步恢复；用户在绘制期间导航时，较新的导航目标优先。文档、表格、集合、媒体和 Agent 内容由各自的视图或导航路径管理加载状态。
- Agent 事件订阅保持较早注册，避免漏掉实时事件。运行状态、历史补齐和 workspace 快照在准入后加载，并遵循当前工作区目标；隐藏会话的补齐限流执行。
- Cloud 初始化与凭据恢复、CLI 路径探测和后台维护在 shell 绘制后启动。设备登记是独立的 fire-and-forget 任务，不参与前台就绪。Cloud schema 初始化使用有界退避；显式登录或退出优先于启动恢复。
- 自动更新检查保留绘制后的延迟并按任务名去重；用户显式检查仍立即执行。Onboarding 和上次更新结果提示延后展示，避免多个提示同时出现。
- 笔记索引、媒体维护和文件监视器属于后台服务，不阻塞阶段 2。离线笔记本根目录由独立重试流程绑定；维护失败通过各自的状态和重试入口处理。

阶段 3 任务各自决定重试方式。例如，笔记链接修复有有限次延迟重试；Agent 状态可由 Agent 界面请求刷新；Agent 会话可在监听器恢复或窗口重新聚焦时再次对账；媒体维护有显式重试入口。不要把这些策略集中到阶段 3 准入器。

## 失败与重试

- 阶段 1 或阶段 2 的必需任务失败时保留失败阶段和具体任务，展示重试入口。原生失败先请求现有工作线程重试；前端重新加载以重跑前端准备。
- 阶段 2 失败的重试界面绘制后也可以发送交互完成信号，以释放不依赖工作区的服务；原生初始化失败时不发送该信号。
- 阶段 2 成功后，内容恢复错误由视图或导航本地展示，不回退工作台启动状态。
- 原生在 120 秒内没有收到交互完成信号时，会用 `interactive-timeout-degraded-release` 释放独立服务以保证活性；该超时不能证明 shell 已绘制。

## 代码入口

- 阶段状态与协调：`app/flowix-desktop/src/app/startup.rs`
- 原生准备与绘制后服务：`app/flowix-desktop/src/app/bootstrap.rs`
- 前端工作台启动与目标恢复：`app/flowix-web/app/main-window-startup.ts`
- 阶段 3 准入和按名去重：`app/flowix-web/lib/startup-stage3.ts`
- 详细并发、维护和状态交付约定：[`STARTUP-LIFECYCLE.md`](./STARTUP-LIFECYCLE.md)

新增阶段 1 任务应检查成功记录、完成后跳过和失败重试。新增阶段 2 任务应检查依赖顺序、失败重试和重复挂载去重。新增阶段 3 任务应检查准入前不会执行、同名任务不会重复启动，并验证该功能自己的失败和重试策略。

## 启动并发补充

- 遗留 Agent loading 标记必须在原生 ready 发布前清理，避免误清除本次启动中新建的消息状态。
- Agent 一次性 workspace 快照与 effect 的订阅生命周期分开。重挂载可复用初始化 Promise，但每个订阅必须独立恢复变化队列和监听重连补齐；异步重载失败需要被观察。
- 首屏后的 watcher 绑定、全量重绑和离线根重试，在 watcher 锁内通过 `watcher::runtime::read_registered_notebooks` 读取最新注册表。该入口使用独立 MemoFile facade，不获取 AppState 的全局 MemoFile 锁，避免与文档自写标记形成反向锁依赖。读取失败保留现有绑定，不将错误解释成空注册表。恢复全量绑定后，为实际绑定成功的根目录补排 reconciliation，覆盖监听空窗期；离线和暂停的根目录不在该分支误报为已恢复。
- 原生日志接受 `stage3-admitted`、`workspace-restore-settled` 和 `workspace-restore-superseded`，用于区分准入、恢复完成和用户导航替代恢复。
